Check each project with “SQL to see if the target function exists.”
ja: 「対象となる関数が存在するのかがわかるSQL」で各プロジェクトをチェックしてみる
```
SET search_path = '';
SELECT pg_catalog.format('%s(%s)', oid::regproc, pg_get_function_identity_arguments(oid::regproc)) AS function_name
FROM pg_proc  
WHERE  
   (pronamespace = 'auth'::regnamespace AND proowner != 'supabase_auth_admin'::regrole)  
   OR (pronamespace = 'storage'::regnamespace AND proowner != 'supabase_storage_admin'::regrole)  
   OR (  
       pronamespace = 'realtime'::regnamespace  
       AND proowner NOT IN (  
           SELECT oid  
           FROM pg_roles  
           WHERE rolname IN ('supabase_admin', 'supabase_realtime_admin')  
       )  
   );
```

# According to the email, functions in the auth schema must be moved to the app_auth schema by 2025-07-28,
# If you don't meet the deadline, they may be automatically moved to another schema or deleted.
# ja: 案内メールによると、2025-07-28 までに auth スキーマの関数を app_auth スキーマに移動する必要があり、
#     期限に間に合わないと 別スキーマに自動的に移動 or 削除されてしまう恐れがある


# 対策手順①
# supabase に手動でSQLを実行する
# ------------------------------------

# (staging/production/local の Supabaseへ手動でSQLを実行する)

# Create app_auth custom schema
# ja: app_auth カスタムスキーマを作成
CREATE SCHEMA IF NOT EXISTS app_auth;

# Move auth schema functions to app_auth schema
# ja: auth スキーマの関数を app_auth スキーマに移動
ALTER FUNCTION auth.user_id() SET SCHEMA app_auth;
ALTER FUNCTION auth.user_type_code() SET SCHEMA app_auth;
ALTER FUNCTION auth.is_member() SET SCHEMA app_auth;
ALTER FUNCTION auth.is_employee() SET SCHEMA app_auth;

# 対策手順②
# Replace source code for supabase migration sql locally in advance
# (Modify and commit previous migration files locally, if you don't do this,
# local supabase postgresDB will start v17 and develop engineers will get an error that they can't create in auth schema during migration)
# ja: 事前に local の supabase migration sql のソースコードを置換
#     (ローカルで過去のマイグレーションファイルを修正してcommitしておく、これをしていないと、
#     local supabaseの postgresDBが v17 を起動し開発するエンジニアは、マイグレーション時に authスキーマに作成できないエラーが起きてしまう)

# Add the following to the first migration file
# ja: 最初のマイグレーションファイルに以下を追記しておく
```
CREATE SCHEMA IF NOT EXISTS app_auth;
```

# Create or replace functions in the auth schema of the migration file with those in the app_auth schema
# ja: マイグレーションファイルの auth スキーマの関数を app_auth スキーマに作成 or 使うように置換
rg -l "auth\.(user_id|user_type_code|is_member|is_employee)" | \
  xargs -I {} perl -i -pe 's/auth\.(user_id|user_type_code|is_member|is_employee)/app_auth.$1/g' {}
